## pstack GPT seat (from the gpt-seat plugin)

The `Agent` tool only accepts Claude family names (`opus`, `fable`, `sonnet`, `haiku`), so the pstack model sheet lists Claude models only. OpenAI models join three pstack panels through the helper `__CODEX_SEAT__`, which runs `codex exec` and prints the model's final answer.

Usage: `printf '%s' "$PROMPT" | __CODEX_SEAT__ [--browser] [--write] <model> [effort] [cwd]`. Without `--write` shell filesystem access is read-only (tests/builds that write caches fail). MCP/browser operations have separate permissions; this sandbox does not make browser actions read-only. With `--write` Codex may edit files under `cwd`, so pass only a git worktree reserved for that seat, never the main working tree. Efforts: low, medium, high, xhigh, max. The seat model is `gpt-6-astra`; a cheap second opinion may use `gpt-6.1-sol` (fall back to `gpt-6-sol` if rejected). Network is off inside the sandbox, so before a run that needs tests, link the main tree's dependency directories (`node_modules`, `.venv`, `vendor`) into the worktree. Codex cannot commit inside a linked worktree (the worktree's git metadata lives outside its sandbox), so the parent commits the seat's work after reading it.

Before the first GPT seat in a session, run `codex login status` and inspect its exit status and output. Reuse an existing login. If not authenticated, follow the `gpt-seat:login-codex` skill: start `codex login` from the parent Claude Code shell, assist with the browser flow using available tools, and verify success with `codex login status` before launching GPT. Keep authentication outside the GPT seat sandbox and serialize it before parallel seats. Ask for user action only when a browser tool is unavailable or a particular authentication step needs it. For other status errors, diagnose the error instead of assuming a missing login. If login is cancelled or fails, skip GPT seats for this invocation, continue with the Claude panel, and explain why; do not repeatedly start login for each seat.

## Default Claude-to-Codex operation

Claude is the user-facing coordinator: clarify the objective as needed, invoke Codex for login operations and file creation/editing/writing, then verify and integrate its result. This is the default delegation policy, including outside pstack panels; a task-specific user assignment takes precedence. Do not merely describe a Codex call or implement the requested edits yourself when delegation is available.

For file tasks, prepare a dedicated git worktree and call `__CODEX_SEAT__ --write gpt-6-astra high <worktree>` with the target files, allowed changes and acceptance criteria. Carry over relevant uncommitted changes and untracked files when required. For files outside Git, stage only the requested files in a disposable Git workspace and integrate the verified result back into the original destination. Claude inspects actual saved contents and diffs and runs relevant checks before reporting success or committing. Preserve the worktree until results are integrated. Use read-only mode for tasks that need no writes.

For browser operations and service logins, invoke `__CODEX_SEAT__ --browser gpt-6-astra high <cwd>`; add `--write` with a dedicated worktree when saving evidence/files. This checks the configured CUA tool and prepends the browser/login operation instructions. The Codex CLI must have the official CUA integration configured and native app access enabled on this Mac. It does not inherit desktop browser tabs automatically: the child discovers connected browsers, or uses native Google Chrome app controls through `cua.getApp("Google Chrome")` when browser providers are unavailable. Honor an explicitly selected browser. Never use raw shell/HTTP, hidden browser state or copied session identifiers to manufacture a connection. Serialize browser tasks and do not operate the same browser from Claude while the child runs. Keep the parent Claude session alive until the child returns success or a concrete human-action blocker. For a bounded foreground Bash call, explicitly use a sufficient timeout (for example 600000 ms) and `run_in_background: false`. If Bash still returns a running task, retrieve its result with the available task-output mechanism before ending the turn; a task ID or process launch is not completion. Do not promise a later notification from a print-mode Claude process that is about to exit. Reuse existing logins and normal autofill, verify authenticated UI, and distinguish existing-session reuse from a new interactive sign-in. The helper checks configuration only; unavailable UI access must be reported as a concrete blocker, not success. Human-only steps and action-time confirmations remain in force.

Codex's own authentication is the bootstrap exception: the parent starts `codex login` and follows `gpt-seat:login-codex` before launching a seat. Never ask an unauthenticated Codex process to authenticate itself. Delegation is not authorization for additional services, broader permissions or external actions. Do not include secrets in prompts or repository/log files, disable protections, or repeat a failed/cancelled authentication loop.

Add the GPT seat in these pstack skills, on top of the Claude entries from the sheet (do not replace them):

- `pstack:interrogate`: one extra reviewer, "Reviewer G". Prepare a review worktree first: `git worktree add --detach <tmp>/review HEAD`; when the review covers uncommitted changes, apply them with `git diff HEAD | git -C <tmp>/review apply` and copy the untracked files that `git status --porcelain` lists; link dependency directories as above. Then run `__CODEX_SEAT__ --write gpt-6-astra xhigh <tmp>/review` with the same reviewer prompt, rubric and diff as the Claude reviewers, plus one line: "You may run builds and tests. Report findings; do not propose fixes as patches." Run it in the background with Bash while the Claude reviewers run, merge its findings like any other reviewer, name it `gpt-6-astra` in the Reviewers list, and remove the worktree afterwards with `git worktree remove --force`.
- `pstack:architect`: one extra runner through `__CODEX_SEAT__ --write gpt-6-astra high <its candidate directory>` with the same task; it writes its sketch and rationale there. Judge it beside the Claude runners.
- `pstack:arena`: one extra runner. Give it its own worktree like every other candidate (Phase A), then run `__CODEX_SEAT__ --write gpt-6-astra high <that worktree>` with the same task prompt and output instructions, as a Bash call with `run_in_background: true`, in the same message as the Claude runners. Commit its result yourself afterwards. The cross-judge does not use the GPT seat: from the sheet's `arena cross-judge pool`, pick the entry that is not the parent session's model.
- Implementation delegate: use Codex by default for the implementation/file-editing delegate unless the user assigns another implementer. Run it as `__CODEX_SEAT__ --write gpt-6-astra high <delegate worktree>` with the same brief instead; the worktree, the review, the commit and the verification stay with Claude as poteto-mode requires.

Never run `codex` with `--dangerously-bypass-approvals-and-sandbox` or `danger-full-access` from a pstack skill.
