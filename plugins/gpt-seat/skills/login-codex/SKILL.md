# Sign in to Codex from Claude Code

This is the bootstrap exception to the default Claude-to-Codex delegation policy: Codex cannot execute tasks before it is authenticated. The parent Claude starts this flow. For other services, delegate login to an already-authenticated Codex session with the required browser/app tools; the CLI wrapper does not automatically inherit desktop tools. Confirm that a real delegation channel and those tools exist, or report the precise limitation and minimal handoff.

1. Check that `codex` is available, then run `codex login status` and inspect its exit status and output. If already authenticated, reuse the login and return successfully; do not log out or replace credentials. If the CLI is missing, help install it following the setup instructions before continuing. Distinguish an unauthenticated result from other CLI or network errors; report and resolve those errors instead of repeatedly starting login.
2. If authentication is needed, run `codex login` from Claude Code's shell tool. Keep the process alive using the tool's background/session support while completing the browser flow. Run login in the parent environment, outside the GPT seat's sandbox, and start only one login process at a time. Do not request a second confirmation when the user already requested setup or login.
3. Use available browser/computer tools to open the official login URL emitted by that process and continue the authorized sign-in flow, including an existing browser session and account selection when the intended account is known. First use any available, already-authorized Codex browser session or parent browser tools. If no such tools or delegation channel are available, explain that specific limitation and request only the necessary browser step while the login process remains running. If a password, passkey, MFA challenge, CAPTCHA, or ambiguous account choice requires user action, ask only for that step and continue afterwards. Do not ask the user to paste passwords, one-time codes, tokens, or credential files into chat, and do not record them in repository files or logs you create.
4. If the normal browser flow fails because a browser or localhost callback is unavailable, stop the previous login process before trying `codex login --device-auth`. This requires device-code login to be enabled in the account or workspace. Complete the official flow with available browser tools or direct the user to the instructions shown in their own terminal; do not copy device codes into chat or persist them. If the fallback is unavailable, report the specific blocker rather than looping or changing account security settings automatically.
5. Wait for the login command to finish successfully, then run `codex login status` again. Only this successful check confirms authentication; opening a page alone does not. Resume the setup or pending GPT seat after verification. If cancelled or unsuccessful, report that authentication is incomplete and skip the GPT seat for this invocation, allowing the Claude panel to continue. Do not retry for every parallel seat.

Authentication commands and browser tools remain subject to their normal permissions. Do not disable sandboxing or approval protections to log in. Authentication is not proof that a particular model is available; handle model access errors separately.
